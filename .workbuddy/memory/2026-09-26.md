# 2026-09-26

## 站点迁移到 Cloudflare Pages（可行性 + 已备好部署件）
- 用户问能否部署到 Cloudflare。结论：**能，而且比 GitHub Pages 更适合**（Pages Functions 能跑云存档，
  不再依赖已 502 的阿里云服务器；静态流量不限量）。
- 官方额度核对（已 WebSearch 确认）：Pages 免费版 20,000 文件 / 单文件 25 MiB / 500 构建每月 /
  100 自定义域名 / 静态流量不限；R2 免费 10GB + 100 万 Class A(写) + 1000 万 Class B(读) 每月。
  本站 320 文件 / 88.4MB / 最大单文件 10.9MB → 全部合规。
- 新增 `functions/xuanmen-save.js`：Pages Functions 版云存档（R2 绑定变量名必须 `SAVES`），
  接口同域 `/xuanmen-save`，ping/load/POST 三个动作，512KB 上限 + 存档码 regex + sha256 文件名。
  **Node 单元测试 7 个场景全过**（ping/坏码/空读/写入/读取/超限/未绑定）。
  坑：Node ESM 在 Windows 导入绝对路径必须写 `file:///F:/...`，否则 ERR_UNSUPPORTED_ESM_URL_SCHEME。
- 客户端（`build_xuanmen.py` 的 CLOUD_JS）新增 `detectApi()`：没有手动配置时先探测
  `location.origin + '/xuanmen-save?action=ping'`，命中（service==='xuanmen-save'）就用同域接口，
  否则回退 `https://www.yhtaoism.com/xuanmen-save/save.php`。这样 Cloudflare 部署后无需改任何代码。
- 新增 `Cloudflare部署指南.md`：对比表 + wrangler 一条命令部署 + R2 绑定步骤 + 自定义域名 + 注意事项。
- 部署命令：`npx wrangler pages deploy . --project-name=ocean-stars [--exclude .workbuddy --exclude .git]`
- 复测：全站 22 页 200、0 死链、0 缺资源。
- **用户实操反馈（网页拖拽上传）踩到两个坑**：
  1. 后台「上传并部署」拖静态文件**不支持 Pages Functions**（官方硬限制，页面有黄字警告）→
     functions/ 带不上，只有 wrangler 部署或 Git 集成才支持。
  2. 用户直接拖了 `F:\ocean-stars-v2` 整夹（388 文件），**把 .workbuddy（含 security/管理口令.txt）也拖进去了**，
     及时叫停（尚未点部署，无泄露）。教训：任何时候都不要拖站点根目录整夹。
- 解决方案（已落地）：
  - `scripts/deploy_cloudflare.py`：打包干净副本到 `F:\ocean-stars-deploy`（排除 .workbuddy/.git/server-api/scripts，
    315 文件 88.3MB，已验证 functions/ 在内、.workbuddy 不在）；`--push` 参数自动调
    `npx -y wrangler@latest pages deploy F:\ocean-stars-deploy --project-name=ocean-stars`（npx 定位到托管 node 目录）。
  - 关键事实（已搜索确认）：**wrangler pages deploy 只忽略固定清单（_worker.js/_redirects/_headers/_routes.json/functions/.DS_Store/node_modules/.git/.wrangler），
    不读 .gitignore、无 --exclude 参数** → 必须先 stage 干净副本。
  - 备选方案：`server-api/cloudflare-worker/xuanmen-save-worker.js`（独立 Worker 版，fetch handler + R2 绑定 SAVES），
    适合纯网页操作：建 Worker → 粘贴代码 → Settings→Bindings 加 R2（变量名 SAVES）→ 客户端面板「修改」填 worker 地址。
  - 用户 Cloudflare 账号的 workers.dev 子域是 fishsea1984。
- **后续踩坑（帮用户代跑部署时）**：
  - `deploy_cloudflare.py` 原先用 `shutil.rmtree` 重建 staging，被本机 safe-delete 保护拦下（315>50 阈值）→
    改为**增量同步**（覆盖写入 + 只删源站已无的残留），已验证通过。写涉及大量文件删除的脚本时注意这个护栏。
  - **本机环境跑不了 wrangler**：npx 能装，但 workerd 原生模块加载崩溃；npm 回滚清理也被护栏拦。
    → 我无法代跑部署，只能给用户命令让他自己在系统终端跑（前提是装了 Node）。
  - 网页上传 88MB 时「部署」按钮在上传完成前是灰的（用户报"点不了"），多半是上传未完成/卡住。
  - **更优路径（应优先推荐）**：Pages → Connect to Git 连 GitHub 仓库，云端拉取，无需浏览器上传 88MB，且支持 Pages Functions。
